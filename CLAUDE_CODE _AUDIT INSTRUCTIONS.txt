PHASE 3 — USER FLOW VERIFICATION
════════════════════════════════════════════

Trace every major user flow through the actual code. For each flow, follow the execution path from UI trigger → API call → handler → database → response → UI update. Report where the chain breaks, is incomplete, or has no tests.

FLOWS TO TRACE:

  FLOW 1: New User Registration
    - Landing page → sign up form → validation → API call → DB write → email verify → login redirect
    - Find: the registration endpoint, the DB model, the validation logic, the email trigger
    - Report: Is each step implemented? Does it persist? Is it tested?

  FLOW 2: User Login + Session
    - Login form → auth check → token/session creation → redirect → protected route access
    - Find: auth middleware, token storage, refresh logic
    - Report: Token expiry handled? Refresh implemented? Logout clears state?

  FLOW 3: Artist Page Creation + Customization
    - User upgrades/opts into artist page → customization UI → save settings → public view
    - Find: the artist page model, the customization fields, the public render path
    - Report: What customization options actually exist in the DB schema? What's wired vs. placeholder?

  FLOW 4: Artist Page Public View
    - Unauthenticated visitor hits /artist/[slug] → page loads → media plays → follow CTA
    - Find: the public route, data fetching, media rendering
    - Report: Is it SEO-ready? Server-side rendered? Does it work without auth?

  FLOW 5: Post/Content Creation
    - User creates post (text/image/video) → uploads media → publishes → appears in feed
    - Find: the post model, the upload handler, the feed query
    - Report: File size limits? Upload progress? Feed ordering logic?

  FLOW 6: Feed / Home Timeline
    - User loads home feed → sees posts from followed accounts → infinite scroll / pagination
    - Find: the feed query, pagination logic, follow/unfollow model
    - Report: N+1 query risk? Pagination implemented? Feed personalization or purely chronological?

  FLOW 7: Direct Messaging
    - User opens DMs → starts new conversation → sends message → recipient gets notification
    - Find: the messaging model, WebSocket or polling setup, notification trigger
    - Report: Real-time or polling? Message persistence verified? Read receipts?

  FLOW 8: Notifications
    - Action triggers notification → stored in DB → delivered to user in real-time or on next load
    - Find: notification model, delivery mechanism, read/unread state
    - Report: What events trigger notifications? How are they delivered?

  FLOW 9: Search
    - User searches for accounts/posts/artists → results display → click through to profile
    - Find: the search endpoint, indexing strategy, query logic
    - Report: Full-text search or LIKE queries? Indexed? Artist-specific search?

  FLOW 10: Follow / Unfollow
    - User follows an artist → feed updates → artist follower count updates → user gets confirmation
    - Find: follow model, feed invalidation, count logic
    - Report: Optimistic UI? Race conditions? Duplicate follow protection?

For each flow output:

  FLOW AUDIT: [Flow Name]
  COMPLETE: YES | PARTIAL | BROKEN | NOT IMPLEMENTED
  BROKEN AT: [exact file:line where chain breaks or goes missing]
  EVIDENCE: [what you found vs. what should be there]
  TESTS EXIST: YES | NO

PHASE 4 — SECURITY AUDIT
════════════════════════════════════════════

Check for each of the following. Report every instance found with file:line.

  AUTH & ACCESS CONTROL
  □ Are all protected routes behind auth middleware?
  □ Can a user read/modify another user's private data? (IDOR check)
  □ Can a regular user access artist-only or admin endpoints?
  □ Are JWT secrets/session secrets in env vars (not hardcoded)?
  □ Is token expiry enforced?
  □ Is password hashing using bcrypt/argon2 (not MD5/SHA1/plaintext)?

  INPUT & DATA
  □ Is user input sanitized before DB queries? (SQL injection risk)
  □ Is user input sanitized before rendering? (XSS risk)
  □ Are file uploads validated by content type (not just extension)?
  □ Is there a file size limit on uploads?
  □ Are filenames randomized (no user-controlled filenames on disk)?

  CONFIGURATION
  □ Are there any hardcoded API keys, secrets, or tokens in source files?
  □ Is .env in .gitignore?
  □ Is there a .env.example with all required vars documented?
  □ Are CORS origins explicitly set (not wildcard *)?

  Run: grep -rn "password\|secret\|api_key\|token" --include="*.ts" --include="*.tsx" --include="*.py" \
    | grep -v ".env" | grep -v "test" | grep -v "example" | grep -v node_modules | head -50

  Report every hardcoded secret found as CRITICAL.
